# Конфигурация «BeautySalon» (Салон красоты) — 1С:Предприятие 8.3

Комплексная конфигурация для автоматизации учёта в салоне красоты: склад, цены, бухгалтерский учёт, отчётность и запись клиентов. Проект адаптирован под малый бизнес с возможностью масштабирования и гибкой настройки аналитики без изменения кода.

## 🛠 Стек технологий и архитектура

* **Платформа:** 1С:Предприятие 8.3 (не ниже 8.3.20), управляемое приложение.
* **Библиотеки:** БСП (Библиотека стандартных подсистем) — интеграция и кастомизация (подсистемы: Базовая функциональность, Пользователи, Организации, Печать, Дополнительные отчёты и обработки).
* **Учётные механизмы:** независимый регистр бухгалтерии, план счетов, субконто и виды характеристик для гибкой аналитики.
* **Система отчётности:** СКД (Система компоновки данных) — отчёты по продажам, остаткам, ОСВ.
* **Интеграции и сервисы:** HTTP‑сервисы для приёма запросов на запись клиента (готовы к подключению мобильного приложения).

## 🚀 Ключевой функционал и технические решения

### 1. Складской и товарный учёт
* Контроль остатков и запрет отрицательных остатков при проведении документов.
* Партионный учёт (списание по средней стоимости).
* Регистр сведений «Цены номенклатуры» — хранение и получение актуальных цен в разрезе номенклатуры и вида цены.
* Загрузка цен из файла Excel непосредственно в регистр.

### 2. Бухгалтерский учёт и аналитика
* Реализован бухгалтерский регистр с привязкой к счетам бухгалтерского учёта (хозрасчётный план счетов).
* План видов характеристик и виды субконто — для гибкой настройки аналитики без правки кода.
* Отчёты: анализ движения средств, контроль остатков, анализ продаж (услуг) в разрезе мастеров и номенклатуры, оборотно-сальдовая ведомость (ОСВ) на СКД.

### 3. Продажи, запись и печатные формы
* Печатная форма «Товарная накладная» — сформирована и подключена.
* HTTP‑сервисы: готовы к интеграции для создания визита, подбора услуг и подтверждения записи.
* Логика записи клиента спроектирована с учётом статусов и резервирования времени.

### 4. Мобильная конфигурация (отдельный контур)
* Мобильная конфигурация выгружена в папку `Mobile` репозитория.
* Предназначена для отдельной базы или сборки мобильного приложения.
* Содержит объекты, необходимые для автономной работы логики записи и передачи данных через HTTP‑сервисы основной конфигурации.
* ⚠️ **Важно:** не загружайте файлы из корня и папки `Mobile` в одну и ту же базу — это приведёт к конфликту объектов.

## 💻 Инструкция по развертыванию проекта для тестирования

### Вариант 1. Загрузка информационной базы (Рекомендуемый, с демо-данными)

1. Скачайте файл резервной копии базы `BeautySalon_Demo.dt` (`BeautySalon_Demo_Mobil.dt`мобильной конфигруации) по ссылке на [Яндекс_Диск](https://disk.yandex.ru/d/2vfhGQEWt4rnVg).
2. Откройте **Стартер 1С:Предприятия** и нажмите кнопку **Добавить**.
3. Выберите *«Создание новой информационной базы»* → *«Создание информационной базы без конфигурации...»*, укажите имя и каталог на диске.
4. Запустите созданную базу в режиме **Конфигуратор**.
5. В верхнем меню выберите **Администрирование → Загрузить информационную базу…** и выберите скачанный файл `.dt`.
6. После завершения загрузки нажмите `F5` для запуска в режиме пользователя.

> Этот вариант оптимален для быстрого тестирования функционала и проверки отчётов.

---

### Вариант 2. Сборка из исходных файлов репозитория (для анализа кода и доработок)

#### Для основной конфигурации (Салон красоты)

1. Создайте чистую информационную базу без конфигурации и запустите её в режиме **Конфигуратор**.
2. Включите возможность изменения: **Конфигурация → Открыть конфигурацию**.
3. Выберите меню **Конфигурация → Загрузить конфигурацию из файлов…**.
4. Укажите путь к **корню репозитория** (папка, где лежат `Catalogs`, `Documents` на верхнем уровне).
5. После успешной загрузки структуры выберите **Конфигурация → Обновить конфигурацию базы данных (F7)**.

#### Для мобильной конфигурации (отдельная база)

1. Создайте **отдельную пустую информационную базу** (не ту же, что для основной конфигурации).
2. Запустите её в режиме **Конфигуратор** и откройте конфигурацию.
3. **Конфигурация → Загрузить конфигурацию из файлов…**
4. В качестве пути укажите папку `Mobile` внутри репозитория (`.../Salon/Mobile`).
5. Выполните **Конфигурация → Обновить конфигурацию базы данных (F7)**.

> Такой подход позволяет независимо тестировать мобильную логику и HTTP‑сервисы, не смешивая объекты.

## 📦 Инженерные особенности и ценность проекта

* **Разделение контуров:** основная конфигурация и мобильная часть хранятся в одном репозитории, но предназначены для разных баз — это упрощает совместную разработку и контроль версий.
* **Гибкая аналитика:** структура учёта (субконто, план счетов, характеристики) позволяет настраивать аналитику без изменения кода, что снижает стоимость доработок.
* **Автоматизация контроля остатков:** устранены ручные проверки и риск ошибок при списании — это ускоряет закрытие смены и повышает точность управленческих данных.
* **Готовность к интеграции:** HTTP‑сервисы спроектированы как точка входа для мобильного приложения и внешних систем.
* **Git‑практика:** настроен `.gitignore` для исключения файлов базы (1Cv8.1CD), кэша и логов; в репозитории хранится только код конфигурации (XML‑выгрузки).

## 💡 Рекомендации по доработкам и работе с кодом

* Все изменения выполняйте в **Конфигураторе**, затем выгружайте конфигурацию в файлы и фиксируйте изменения коммитами с понятными сообщениями.
* Для мобильной части используйте отдельную базу и отдельную ветку Git (при необходимости) — это снижает риск конфликтов при совместной разработке.
* При добавлении новых подсистем БСП обязательно проверяйте совместимость версий и актуализируйте зависимости.
